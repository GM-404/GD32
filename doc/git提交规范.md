在 Git 提交时，为了让提交信息更专业、清晰，建议遵循 **“类型 (范围): 简明描述”的格式，并结合开发场景选择合适的类型前缀和范围说明 **。
一、“类型” 前缀推荐
类型	含义	适用场景
feat	新增功能（Feature）	首次实现功能、新增模块 / 算法
fix	修复缺陷（Bug Fix）	修复逻辑错误、性能问题
refactor	重构代码（无功能变更，仅优化结构）	代码逻辑简化、函数拆分合并
perf	性能优化（Performance）	算法提速、内存占用优化
docs	文档变更（Documentation）	README、注释、设计文档修改
style	代码风格（不影响逻辑，如格式、空格、命名）	变量重命名、代码格式化
test	测试相关（新增 / 修改测试用例、测试工具）	单元测试、集成测试补充
chore	杂项（构建流程、依赖管理、工程配置等非业务逻辑变更）	CMake 配置、工具链升级

范围用于明确修改影响的模块、文件或功能点，让团队快速定位变更领域。结合你的场景（雷达信号处理、CFAR 检测、FFT 等），推荐以下范围：
范围	含义
cfar	CFAR 检测模块
fft	FFT 算法模块（1D/2D/IDFFT 等）
data-parse	数据解析 / 日志模块
doc	文档（如 README）
test	测试模块（用例、验证逻辑）
build	构建流程（CMake、编译配置）
algo	算法层（如多帧检测、杂波去除）
